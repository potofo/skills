## ドキュメント処理スキル

### docx

**目的**: Word文書（.docx）の作成、読み取り、編集、操作

**主な機能**:
- **新規文書作成**: docx-js（JavaScript）を使用
- **既存文書編集**: XML展開 → 編集 → 再パック
- **コンテンツ読み取り**: pandocまたはXMLアクセス
- **変更履歴**: 挿入、削除、コメントの追跡
- **高度な機能**: 表、画像、ハイパーリンク、脚注、目次、ヘッダー/フッター

**技術詳細**:
- .docxファイルはXMLを含むZIPアーカイブ
- ページサイズ: US Letter（12,240 x 15,840 DXA）
- スタイル: Arial（デフォルト）、見出しのオーバーライド
- 表: DXA単位で幅を設定（パーセンテージは避ける）

**一般的なコマンド**:
```bash
# .docから.docxに変換
python scripts/office/soffice.py --headless --convert-to docx document.doc

# テキスト抽出
pandoc --track-changes=all document.docx -o output.md

# 文書の展開/再パック
python scripts/office/unpack.py document.docx unpacked/
python scripts/office/pack.py unpacked/ output.docx --original document.docx
```

**トリガー条件**:
- Word文書、.docxファイルの言及
- レポート、メモ、レター、テンプレートの作成
- 変更履歴、コメントの操作

**ライセンス**: プロプライエタリ（LICENSE.txt参照）

### webapp-testing

**目的**: Playwrightを使用したローカルWebアプリケーションのテスト

**主な機能**:
- フロントエンド機能の検証
- UIの動作のデバッグ
- ブラウザスクリーンショットのキャプチャ
- ブラウザログの表示
- サーバーライフサイクル管理（`scripts/with_server.py`）

**ワークフロー**:
1. 静的HTMLか動的Webアプリかを判断
2. サーバーが実行中でない場合は`with_server.py`を使用
3. 偵察してからアクション（ナビゲート、スクリーンショット、セレクタ識別）
4. 発見したセレクタでアクションを実行

**例**:
```bash
# 単一サーバー
python scripts/with_server.py --server "npm run dev" --port 5173 -- python your_automation.py

# 複数サーバー
python scripts/with_server.py \
  --server "cd backend && python server.py" --port 3000 \
  --server "cd frontend && npm run dev" --port 5173 \
  -- python your_automation.py
```

**トリガー条件**:
- ローカルWebアプリケーションのテスト
- フロントエンド機能の検証
- UIの動作のデバッグ

### doc-coauthoring

**目的**: ドキュメント共同作成のための構造化ワークフロー

**主な機能**:
- 3段階のワークフロー
  1. **コンテキスト収集**: ユーザーがコンテキストを提供、Claudeが質問
  2. **洗練と構造化**: ブレインストーミングと編集を通じて各セクションを構築
  3. **読者テスト**: 新しいClaude（コンテキストなし）でドキュメントをテスト
- ドキュメントタイプ: 技術仕様、決定ドキュメント、提案、PRD、RFC

**ワークフロー**:
1. ドキュメントタイプ、対象読者、望ましい影響を特定
2. テンプレートまたは既存ドキュメントを読み込む
3. コンテキストを収集し、質問に答える
4. 各セクションを反復的に洗練
5. 新しいClaudeインスタンスでテスト

**トリガー条件**:
- ドキュメント、提案、技術仕様、決定ドキュメントの作成
- PRD、設計ドキュメント、RFCの言及

## メタスキル

### skill-creator

**目的**: 新しいスキルの作成と既存スキルの改善

**主な機能**:
- スキルの作成と反復的改善
- テストケースの作成と実行
- 定性的および定量的評価
- ベンチマーク比較
- 説明の最適化（トリガー精度向上）
- スキルのパッケージ化

**ワークフロー**:
1. **意図の把握**: スキルが何をすべきか、いつトリガーすべきか
2. **インタビューと調査**: エッジケース、入出力形式、成功基準
3. **SKILL.mdの作成**: 名前、説明、指示、例
4. **テストケースの作成**: 2-3個の現実的なテストプロンプト
5. **実行と評価**: サブエージェントで実行、フィードバックを収集
6. **改善**: フィードバックに基づいてスキルを改善
7. **繰り返し**: 満足するまで繰り返す

**高度な機能**:
- ブラインド比較（2つのバージョンの厳密な比較）
- 説明の最適化（トリガー評価クエリの生成と最適化）
- パッケージ化と提示

**トリガー条件**:
- スキルの作成、編集、最適化
- スキルのテスト、ベンチマーク
- 説明のトリガー精度の最適化

**ライセンス**: LICENSE.txt参照

## スキル使用のベストプラクティス

### 段階的開示

スキルは3レベルの読み込みシステムを使用します：
1. **メタデータ**（名前 + 説明）: 常にコンテキスト内（約100語）
2. **SKILL.md本文**: スキルがトリガーされたときに読み込まれる（理想は500行未満）
3. **バンドルリソース**: 必要に応じて読み込まれる（サイズ無制限）

### スキルの選択

- **クリエイティブタスク**: algorithmic-art、canvas-design、frontend-design
- **ドキュメント処理**: docx、pdf、pptx、xlsx
- **API統合**: claude-api、mcp-builder
- **Webアプリケーション**: web-artifacts-builder、webapp-testing
- **コミュニケーション**: internal-comms、doc-coauthoring
- **スタイリング**: brand-guidelines、theme-factory
- **メタ**: skill-creator

### ライセンス考慮事項

- **オープンソース（Apache 2.0）**: ほとんどのサンプルスキル
- **プロプライエタリ（ソース公開）**: docx、pdf、pptx、xlsx
- 各スキルのLICENSE.txtファイルで具体的な条件を確認
