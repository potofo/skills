## スキルディレクトリ構造

各スキルは以下のパターンに従います：

```
skill-name/
├── SKILL.md                    # 必須：指示とメタデータ
├── LICENSE.txt                 # ライセンス条項（Apache 2.0でない場合）
├── scripts/                    # オプション：ヘルパースクリプト
│   ├── script1.py
│   └── script2.js
├── references/                 # オプション：リファレンスドキュメント
│   ├── guide1.md
│   └── guide2.md
├── assets/                     # オプション：静的リソース
│   ├── template.html
│   └── icon.png
├── templates/                  # オプション：ファイルテンプレート
│   └── template_file.ext
└── evals/                      # オプション：評価テストケース
    └── evals.json
```

## 主要な規約

### スキル命名

- **ディレクトリ名**: ハイフン付き小文字（例：`algorithmic-art`）
- **フロントマター名**: ディレクトリ名と一致
- **説明**: 包括的なトリガー条件と使用例

### 段階的開示

スキルは3レベルの読み込みシステムを使用します：
1. **メタデータ**（名前 + 説明）: 常にコンテキスト内（約100語）
2. **SKILL.md本文**: スキルがトリガーされたときに読み込まれる（理想は500行未満）
3. **バンドルリソース**: 必要に応じて読み込まれる（サイズ無制限）

### ファイル構成

- **SKILL.mdを500行未満に保つ**: 大きなコンテンツはリファレンスファイルに移動
- **リファレンスファイルを明確に**: いつ読むべきかのガイダンスを含める
- **大きなリファレンス（300行以上）**: 目次を含める
- **繰り返し作業用のスクリプト**: 共通操作を実行可能なスクリプトとしてバンドル

### ドメイン構成

複数のフレームワーク/プラットフォームをサポートするスキルの場合：

```
skill-name/
├── SKILL.md                    # ワークフローと選択ロジック
└── references/
    ├── framework1.md
    ├── framework2.md
    └── framework3.md
```

Claudeはコンテキストに基づいて関連するリファレンスファイルのみを読み込みます。

## 特殊ディレクトリ

### ドキュメントスキル（プロプライエタリ）

`docx/`、`pdf/`、`pptx/`、`xlsx/`スキルはソース公開ですがオープンソースではありません。本番品質のスキルパターンを示しています：

- 包括的なXML操作ガイド
- 複雑な操作のためのスクリプトベースのワークフロー
- 広範な検証とエラー処理
- テンプレートベースのアーティファクト生成

### Skill Creator

`skill-creator/`スキルはメタスキルで、他のスキルの作成と改善を支援します：

- 評価フレームワークを含む
- ベンチマーク比較ツール
- 説明最適化スクリプト
- HTMLベースのレビューインターフェース

### MCP Builder

`mcp-builder/`スキルはMCPサーバー開発をガイドします：

- 言語固有の実装ガイド
- プロトコルドキュメントリファレンス
- 評価作成ワークフロー
- 品質チェックリスト

## 設定ファイル

### Claude Codeプラグイン

`.claude-plugin/marketplace.json`は、Claude Codeでスキルをインストールするためのプラグインマーケットプレイス設定を定義します。

### Git設定

`.gitignore`は以下を除外します：
- `.DS_Store`（macOS）
- `__pycache__/`（Python）
- `.idea/`、`.vscode/`（IDE設定）

## スキルの操作

### 新しいスキルの作成

1. `template/SKILL.md`を出発点としてコピー
2. スキルディレクトリ構造の規約に従う
3. SKILL.mdを焦点を絞って500行未満に保つ
4. 必要に応じてバンドルリソースを追加
5. 評価フレームワークでテスト（客観的なスキルの場合）

### 既存スキルの変更

1. ディレクトリとフロントマター名を保持
2. 既存のライセンス条項を維持
3. スキル内の確立されたパターンに従う
4. skill-creator評価ワークフローで変更をテスト

### スキルのパッケージ化

`scripts.package_skill`を使用して、スキルディレクトリ全体をバンドルした配布可能な`.skill`ファイルを作成します。
